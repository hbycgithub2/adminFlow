## 🔍 关键发现：自动模式的真实情况

### 自动模式的代码分析

```java
// generateWithSingleTTS() - 第2-3步
String speaker = segments.get(0).getSpeaker();  // ← 只用第一个segment的speaker

TTSRequest request = TTSRequest.builder()
        .text(fullText)
        .speaker(speaker)  // ← 整段文本用同一个speaker
        .build();

byte[] fullAudio = ttsService.generateSpeechBytes(request);
```

**核心问题：**
- ❌ 自动模式**不支持多音色**
- ❌ 只使用第一个segment的speaker
- ❌ 整段文本用同一个音色生成

**示例：**
```
文档内容：
  小明（BV700）：你好
  小红（BV123）：你好

自动模式处理：
  fullText = "小明：你好小红：你好"
  speaker = BV700（小明的音色）
  
TTS调用：
  TTS("小明：你好小红：你好", speaker=BV700)
  
结果：
  ❌ 小红的"你好"也用小明的音色（BV700）
  ❌ 完全没有音色区分
```

## 🔧 针对场景2的最优方案

### 方案：修复手动模式（按paragraphId合并）

#### 核心思路

**问题诊断：**
```
当前手动模式的bug：
1. 第一步：按paragraphId合并成Line
2. 第二步：按speaker匹配AudioSegment到Line
3. 当段落内有多个speaker时 → 映射断裂 → 字幕不准
```

**解决方案：**
```
统一合并逻辑为paragraphId：
1. TTS生成时：按paragraphId合并（而不是按speaker）
2. DialogSegment构建时：按paragraphId合并（已经这样做了）
3. 匹配逻辑：直接按索引一一对应（无需复杂匹配）
```

#### 详细设计

**Step 1：修改合并逻辑**

```java
// 当前逻辑（TextSegmentMerger.merge）：
// 按speaker合并
if (segment.getSpeaker().equals(currentSpeaker)) {
    merge();
}

// 修改后逻辑：
// 按paragraphId合并
if (segment.getParagraphId().equals(currentParagraphId)) {
    merge();
    // 注意：如果段落内有多个speaker，使用第一个speaker
}
```

**Step 2：简化匹配逻辑**

```java
// 当前逻辑（buildDialogSegments）：
// 复杂的speaker匹配
while (audioIndex < audioSegments.size()) {
    if (!audioSegment.getSpeaker().equals(line.speaker)) {
        break;  // speaker不同，停止匹配
    }
}

// 修改后逻辑：
// 直接按索引一一对应
for (int i = 0; i < lines.size(); i++) {
    Line line = lines.get(i);
    AudioSegment audio = audioSegments.get(i);  // ← 直接对应，简单！
}
```

#### 处理效果对比

**文档示例：**
```
段落1（paragraphId=1）：
  小明（BV700）：你好
  小红（BV123）：你好

段落2（paragraphId=2）：
  小明（BV700）：再见
```

**当前手动模式（有bug）：**
```
TTS生成（按speaker合并）：
  AudioSegment1：小明：你好（BV700）
  AudioSegment2：小红：你好（BV123）
  AudioSegment3：小明：再见（BV700）

构建Line（按paragraphId合并）：
  Line1：小明：你好小红：你好（paragraphId=1）
  Line2：小明：再见（paragraphId=2）

匹配AudioSegment（按speaker匹配）：
  Line1（speaker=BV700）：
    → AudioSegment1（BV700）✅ 匹配
    → AudioSegment2（BV123）❌ speaker不同，停止
    → ❌ 只匹配到AudioSegment1
    → ❌ "小红：你好"的音频丢失！
  
  Line2（speaker=BV700）：
    → AudioSegment2（BV123）❌ speaker不同，跳过
    → AudioSegment3（BV700）✅ 匹配
    → ⚠️ 匹配到了AudioSegment3，但AudioSegment2被遗漏

结果：
  ❌ 字幕显示"小明：你好小红：你好"
  ❌ 音频只有"小明：你好"
  ❌ 完全不同步！
```

**修复后手动模式（按paragraphId）：**
```
TTS生成（按paragraphId合并）：
  AudioSegment1：小明：你好小红：你好（BV700）← 用第一个speaker
  AudioSegment2：小明：再见（BV700）

构建Line（按paragraphId合并）：
  Line1：小明：你好小红：你好（paragraphId=1）
  Line2：小明：再见（paragraphId=2）

匹配AudioSegment（按索引一一对应）：
  Line1（index=0）→ AudioSegment1（index=0）✅
  Line2（index=1）→ AudioSegment2（index=1）✅

结果：
  ✅ 字幕显示"小明：你好小红：你好"
  ✅ 音频是"小明：你好小红：你好"
  ✅ 完美同步！
  
⚠️ 注意：
  - 段落1整体用BV700音色（小明的音色）
  - "小红：你好"也是BV700音色（而不是BV123）
  - 丧失了段落内的音色差异
```
