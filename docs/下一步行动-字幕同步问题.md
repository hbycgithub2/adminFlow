## 🐛 发现的核心问题

### 问题：TTS生成的音频包含不可预测的静音

**问题链条：**

```
TTS生成音频 → 包含开头/结尾静音（0.03-0.1秒）
     ↓
FFprobe读取 → 包含静音的完整时长
     ↓
WhisperX识别 → 只识别语音部分，忽略静音
     ↓
字幕时间戳 → 基于WhisperX的纯语音时间戳
     ↓
最终音频 → 包含TTS静音 + 人工停顿
     ↓
结果 → 字幕时间戳与实际音频不匹配
```

**具体表现：**

```
音频实际结构：
[静音0.05s] + [语音1s] + [静音0.1s] + [停顿0.8s] + [静音0.03s] + [语音1s] + ...

WhisperX认为的结构（字幕基于此）：
[语音1s] + [停顿0.8s] + [语音1s] + ...

偏差：0.05s（第1句）→ 0.18s（第2句）→ 累积偏差越来越大
```

## ✅ 已实施的修复（Day 5）

### 核心修复：使用WhisperX实际时长

**代码位置：** `DocumentTTSServiceImpl.java` - buildDialogSegments方法

```java
// ✅ 使用WhisperX返回的实际语音时长（而不是FFprobe时长）
double segmentDuration = segmentResult.actualSpeechDuration > 0 ? 
    segmentResult.actualSpeechDuration :  // ← WhisperX实际时长（纯语音）
    (audioSegment.getAccurateDuration() != null ? 
        audioSegment.getAccurateDuration() : 
        calculateAudioDuration(...));

segmentStartTime += segmentDuration;

// 加上停顿时间
if (audioSegment.getNeedPause() != null && audioSegment.getNeedPause()) {
    double pauseSec = (audioSegment.getPauseDuration() != null ? 
                      audioSegment.getPauseDuration() : 800) / 1000.0;
    segmentStartTime += pauseSec;
}
```

**理论效果：**
- ✅ 字幕时间戳完全基于WhisperX识别的实际语音
- ✅ 自动忽略TTS生成的静音
- ✅ 停顿时间精确累加
- ✅ 预期同步精度：< 50ms
