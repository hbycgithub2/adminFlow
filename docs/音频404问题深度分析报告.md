## 🎯 根本原因

**核心问题**：**文件保存路径** 和 **文件访问路径** 不一致！

### 问题1：文件实际保存在哪里？

**DocumentTTSServiceImpl.java** (第92行):
```java
String fileName = taskId + "." + voiceConfig.getFormat();
Path outputDir = Paths.get(config.getOutputDir(), "documents");  // ⭐
Path audioFile = outputDir.resolve(fileName);
Files.write(audioFile, audioResult.getAudioData());
```

**VolcengineConfig.java** (第71行):
```java
private String outputDir = "tts";  // ⭐ 默认值是 "tts"
```

**实际保存路径**:
```
相对路径: ./tts/documents/xxx.mp3
绝对路径: D:\code\adminFlow\tts\documents\xxx.mp3  ⭐
          (工作目录 + tts + documents)
```

---

### 问题2：Controller从哪里读取文件？

**TtsResourceController.java** (第36行):
```java
String outputDir = System.getProperty("user.home") + File.separator + "tts-output";  // ⭐
Path filePath = Paths.get(outputDir, "documents", fileName);
```

**实际访问路径**:
```
绝对路径: C:\Users\86152\tts-output\documents\xxx.mp3  ⭐
          (用户主目录 + tts-output + documents)
```

---

### 问题3：两个路径完全不同！

| 对比项 | 保存路径 | 访问路径 | 是否匹配 |
|--------|----------|----------|---------|
| **基础目录** | `D:\code\adminFlow` | `C:\Users\86152` | ❌ |
| **一级目录** | `tts` | `tts-output` | ❌ |
| **二级目录** | `documents` | `documents` | ✅ |
| **文件名** | `xxx.mp3` | `xxx.mp3` | ✅ |

**结论**：文件保存到了 `D:\code\adminFlow\tts\documents\`，但是Controller去 `C:\Users\86152\tts-output\documents\` 找，当然找不到！

---

## 🔧 解决方案

### 方案A：修改TtsResourceController（推荐）⭐

**原理**：让Controller从实际保存路径读取文件

**优点**：
- ✅ 不影响现有保存逻辑
- ✅ 改动最小（只改1个文件）
- ✅ 立即生效

**修改文件**：`TtsResourceController.java`

**修改内容**：
```java
// 修改前：
String outputDir = System.getProperty("user.home") + File.separator + "tts-output";
Path filePath = Paths.get(outputDir, "documents", fileName);

// 修改后：
Path filePath = Paths.get("tts", "documents", fileName);  // ⭐ 使用相对路径
// 或者
Path filePath = Paths.get(System.getProperty("user.dir"), "tts", "documents", fileName);  // ⭐ 使用工作目录
```

---

### 方案B：修改DocumentTTSServiceImpl

**原理**：让保存路径改为用户主目录

**优点**：
- ✅ 文件保存在用户目录，更符合规范

**缺点**：
- ❌ 需要修改配置类
- ❌ 可能影响其他功能

**修改文件**：`VolcengineConfig.java`

**修改内容**：
```java
// 修改前：
private String outputDir = "tts";

// 修改后：
private String outputDir = System.getProperty("user.home") + File.separator + "tts-output";
```

---

### 方案C：统一使用配置（最佳）⭐⭐⭐

**原理**：让Controller和Service都从配置类读取路径

**优点**：
- ✅ 统一管理，易于维护
- ✅ 避免硬编码
- ✅ 修改配置即可切换路径

**修改步骤**：

1. **修改TtsResourceController**：注入VolcengineConfig
```java
@Slf4j
@RestController
@RequestMapping("/tts")
@RequiredArgsConstructor  // ⭐
public class TtsResourceController {
    
    private final VolcengineConfig config;  // ⭐ 注入配置
    
    @GetMapping("/documents/{fileName}")
    public ResponseEntity<Resource> downloadDocumentAudio(@PathVariable String fileName) {
        try {

            Path filePath = Paths.get(config.getOutputDir(), "documents", fileName);
            
            log.info("音频文件路径: {}", filePath.toAbsolutePath());
            
            // ... 后续代码不变
        }
    }
}
```

2. **可选：在application.yml添加配置**
```yaml
volcengine:
  output-dir: ./tts  # 开发环境：项目目录
  # output-dir: ${user.home}/tts-output  # 生产环境：用户目录
```

## 🚀 实施步骤（方案C）

### 步骤1：修改TtsResourceController

```java
package com.hmall.tts.volcengine.controller;

import com.hmall.tts.volcengine.config.VolcengineConfig;  // ⭐ 新增
import lombok.RequiredArgsConstructor;  // ⭐ 新增
import lombok.extern.slf4j.Slf4j;
import org.springframework.core.io.FileSystemResource;
import org.springframework.core.io.Resource;
import org.springframework.http.HttpHeaders;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;

@Slf4j
@RestController
@RequestMapping("/tts")
@RequiredArgsConstructor  // ⭐ 新增
public class TtsResourceController {
    
    private final VolcengineConfig config;  // ⭐ 注入配置
    
    @GetMapping("/documents/{fileName}")
    public ResponseEntity<Resource> downloadDocumentAudio(@PathVariable String fileName) {
        try {
            log.info("请求下载音频文件: {}", fileName);
            
            // ⭐ 从配置读取路径（统一使用DocumentTTSService的保存路径）
            Path filePath = Paths.get(config.getOutputDir(), "documents", fileName);
            
            log.info("音频文件路径: {}", filePath.toAbsolutePath());
            
            // 检查文件是否存在
            if (!Files.exists(filePath)) {
                log.error("音频文件不存在: {}", filePath.toAbsolutePath());
                return ResponseEntity.notFound().build();
            }
            
            // 检查文件大小
            long fileSize = Files.size(filePath);
            log.info("音频文件大小: {} bytes ({} KB)", fileSize, fileSize / 1024.0);
            
            // 创建资源
            Resource resource = new FileSystemResource(filePath.toFile());
            
            // 判断文件格式
            String contentType = "audio/mpeg"; // 默认MP3
            if (fileName.endsWith(".wav")) {
                contentType = "audio/wav";
            } else if (fileName.endsWith(".ogg")) {
                contentType = "audio/ogg";
            }
            
            // 设置响应头
            HttpHeaders headers = new HttpHeaders();
            headers.setContentType(MediaType.parseMediaType(contentType));
            headers.setContentLength(fileSize);
            headers.setCacheControl("no-cache");
            
            log.info("✅ 返回音频文件: {}, 类型: {}, 大小: {} bytes", fileName, contentType, fileSize);
            
            return ResponseEntity.ok()
                    .headers(headers)
                    .body(resource);
            
        } catch (Exception e) {
            log.error("❌ 下载音频文件失败: {}, 错误: {}", fileName, e.getMessage(), e);
            return ResponseEntity.internalServerError().build();
        }
    }
}
```

## 📝 为什么会出现这个问题？

**原因分析**：
1. **不同人开发**：DocumentTTSService和TtsResourceController可能是不同时间/不同人开发的
2. **缺少配置统一**：没有统一的路径配置管理
3. **硬编码路径**：Controller硬编码了路径，没有从配置读取
4. **测试不充分**：可能只测试了视频生成，没有单独测试音频下载

**经验教训**：
- ✅ 文件路径应该统一管理（配置类或application.yml）
- ✅ 避免硬编码路径
- ✅ 生成和访问应该使用相同的路径逻辑
- ✅ 新功能上线前要做端到端测试
